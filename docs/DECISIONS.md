## 2026-09-17 — Правила разработки: ECC + Impeccable + собственный документ

**Решение:** плагины ECC и Impeccable включены глобально. Правила ECC
(`common`, `typescript`) скопированы в `.claude/rules/ecc/` из коммита `8321021`
(ECC 2.2.1). Приоритет — у `docs/DEVELOPMENT_RULES.md`.

**Причина:** плагин ECC не устанавливает правила сам, их нужно копировать вручную.
Копия в проекте фиксирует версию правил.

**Отвергнуто:** глобальные правила в `~/.claude/rules` — версия правил
менялась бы незаметно для проекта.

## 2026-09-17 — Стек и Docker

**Решение:** Node.js 24 + TypeScript, PostgreSQL 17, запуск через docker-compose.
Многоэтапный Dockerfile, приложение работает от пользователя `node`.
Порт БД наружу не публикуется.

**Причина:** одинаковое окружение на любой машине; в рабочем образе нет
dev-зависимостей и исходников TypeScript.

**Отвергнуто:** PostgreSQL 18 — в образе изменился путь хранения данных,
перейдём отдельной задачей при необходимости.

## 2026-09-17 — Монорепо Amare Care: pnpm + Turborepo, NestJS, Next.js

**Решение:** монорепо pnpm 12 + Turborepo. `apps/api` (NestJS, два процесса из
одного образа: `main.ts` — HTTP, `worker.ts` — без HTTP), `apps/site|care|staff`
(Next.js 16), `packages/ui|i18n|api-client`. Пакеты отдают TS-исходники
(«internal packages»), Next транспилирует их через `transpilePackages`.
Первый каркас (`src/index.ts`, корневой Dockerfile и compose) удалён.
Пункт «Порт БД наружу не публикуется» из записи выше остаётся в силе для prod.

**TypeScript 6.0, а не 7.0:** typescript-eslint 8.x поддерживает только TS < 6.1.
Переходим на TS 7, когда линтер его поддержит. api собирается SWC (`nest build`),
`tsc` — только проверка типов.

**Отвергнуто:** TS 7 с обходом peer-зависимости — риск неверной работы линтера;
Biome/oxlint — меньше правил для Next.

## 2026-09-17 — S3: Garage в однонодовом режиме

**Решение:** Garage v2.4 (`dxflrs/garage`), запуск `server --single-node --default-bucket`:
ключ и bucket создаются из `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_BUCKET`.
Admin API не включён. В плане был отдельный контейнер `s3-init` со скриптом
через Admin API — оказался не нужен.

**Причина:** MinIO community не публикует готовые образы; Garage лёгкий и активно развивается.

**Отвергнуто:** MinIO, SeaweedFS (тяжелее в настройке), init-скрипт через Admin API (лишний код).

## 2026-09-17 — Health: живость и готовность раздельно

**Решение:** `GET /health` — всегда 200, без зависимостей (для HEALTHCHECK Docker).
`GET /health/ready` — ping postgres, redis, s3; при сбое 503, причина только в логе сервера.

**Причина:** если liveness зависит от БД, Docker перезапускает здоровый API
при недоступной базе.

## 2026-09-17 — Три compose-файла

**Решение:** `compose.yaml` (база), `compose.override.yaml` (dev, подхватывается
`docker compose up` автоматически), `compose.prod.yaml` (явно через `-f`).
В dev порты postgres, redis и s3 публикуются **только на 127.0.0.1** — для локальных
инструментов. В prod наружу открыт только api. В контейнеры передаются только нужные
переменные, не весь `.env`.

**Причина:** `docker compose up` без флагов даёт dev; prod не запускается случайно.

## 2026-09-17 — Политики безопасности pnpm 12 не ослабляем

**Решение:** оставлены `minimumReleaseAge` (свежие релизы не ставятся) и блокировка
install-скриптов (разрешён только `@swc/core` в `allowBuilds`). Для слишком свежего
`@aws-sdk/client-s3` взята предыдущая версия вместо исключения из политики.

**Причина:** защита от подмены пакетов в цепочке поставок.
